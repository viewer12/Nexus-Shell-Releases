# 在 Mac 上处理两台服务器之间的文件

[English](../multi-server-files.md) · 适用 Nexus Shell 1.7.7 · 更新于 2026 年 9 月 25 日

Nexus Shell 可以保持多个 SSH 会话标签，并提供本地与远程双栏文件视图。偶尔需要把文件从服务器 A 复制到 B 时，可以先下载到 Mac，再切换目标服务器上传。这是通过 Mac 中转的两步复制，不是服务器之间直接传输。

## 先确认是否适合你的任务

| 需要做的事 | 1.7.7 的实际使用方式 |
| --- | --- |
| 保持多个 SSH 连接 | 使用会话标签；输入命令前确认当前服务器。 |
| 双栏浏览文件 | 左侧是 Mac 本地文件，右侧是一台当前选中的远程服务器。 |
| 从 A 复制一个文件到 B | 先下载到本地目录，再切换服务器并上传。 |
| 同时查看两个远程文件树或两个终端 | 不要把多个标签或文件双栏理解成这种分屏布局。 |
| 重复部署或镜像整个目录 | 需要另行验证部署、同步方案；文件上传不等于自动部署。 |

## 先完成一个小文件任务

先用无敏感内容的测试文件和自己有权限的目录验证。你需要两台服务器的 SFTP 访问权限、源文件读取权限和目标目录写入权限。

1. 在 Finder 新建一个本地目录，例如 `server-a-to-b-test`。确认该目录的备份、云同步设置适合存放这份文件。
2. 在「文件」视图选择服务器 A，核对远程路径，把测试文件下载到这个新目录。等待传输完成，避免把未下载完的文件继续上传。
3. 用「文件」视图的连接选择器切换到服务器 B。再次核对服务器名称和目标路径，选用自己有权限的独立暂存目录，不要直接覆盖线上服务配置。
4. 上传本地测试文件。遇到同名冲突时，先核实目标，不要默认替换。
5. 检查目标文件内容及权限。若需要校验字节是否一致，可把目标文件下载到另一个新建目录，在 Mac「终端」中运行 `shasum -a 256`，后接两个加引号的本地文件路径，比较输出的摘要列。摘要相同表示字节一致，不代表内容正确，也不证明所有文件元数据均被保留。
6. 校验完成前保留源文件。后续移入服务目录、重载服务、修改权限或清理都是独立操作。只清理本次明确创建、已经不再需要的测试副本。

这个流程会在 Mac 留下本地副本，也会占用本地磁盘和网络。大规模持续复制，或数据不能落到 Mac 的场景，应选用明确满足要求的传输方式。不能据此承诺保留所有者、ACL 或全部扩展属性。

## 不必每次都移动到最右侧铅笔按钮

在文件路径栏的面包屑区域右键，选择「编辑路径」；也可以双击面包屑区域进入路径编辑。铅笔按钮仍然可用。输入路径后按回车打开，按 Esc 取消。

单击上级目录的面包屑会跳转到该目录，不是编辑路径。终端内「文件」面板的路径栏也提供双击与右键编辑入口。控件名称随界面语言变化；手势未命中时，可使用右键菜单或完整「文件」视图的铅笔按钮。

## 需要命令行传输时

当前 OpenSSH 的 [`scp -3`](https://man.openbsd.org/scp#3) 会让两台远程服务器之间的数据经过执行命令的本地电脑，即使没有显式保存一个本地暂存文件，本地电脑也仍在传输路径中。[`-R`](https://man.openbsd.org/scp#R) 则从源服务器执行复制，要求源服务器能向目标服务器认证。具体选项以 Mac 上的 `man scp` 为准。这是独立的系统 OpenSSH 操作，不是 Nexus Shell 文件视图中的开关。

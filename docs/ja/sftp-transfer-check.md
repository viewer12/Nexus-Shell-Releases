# MacからSFTPで送る前に、保存先と往復転送を確認する

Nexus Shellチーム · 公開2026年10月12日 · 更新2026年10月27日 · [English](../sftp-transfer-check.md) · [中文](../zh-CN/sftp-transfer-check.md)

## 改行と元データを分けて確認する

2026-10-27追記。WinSCPの[公式転送モード](https://winscp.net/eng/docs/transfer_mode)ではText・Binary・ファイル名で選ぶAutomaticと編集時の設定を区別します。別のMacアプリへ移るとき、その設定が自動で移るとは限りません。Nexus Shellの自動LF変換や同じ設定項目を保証する説明ではありません。

1. 元のファイルを保持します。Linuxスクリプトの`^M`やbad interpreterは、改行と先頭のインタープリターのパスを別々に確認します。転送成功は実行できる証拠ではありません。
2. LFが必要なら、エディタで別コピーを作成して変更を確認し、そのコピーを基準にします。画像・ZIP・本番ディレクトリを一括変換しないでください。
3. 独立したテスト用パスへ送り、Macの別の空フォルダへ取り戻します。各コピーに`shasum -a 256`を実行し、保持した基準と照合します。転送中に変わる原件や、同じ原件を2回選ぶ方法では確認できません。
4. 各16 MiB以下の小さな非機密ファイルなら、[ブラウザ内の2ファイル比較（英語UI）](https://nexusshell.app/en/guides/winscp-alternative-for-mac/?utm_source=github-releases&utm_medium=repository&utm_campaign=multi_server_files_202609#compare-your-sftp-files)も使えます。SHA-256とCRLF/LFだけの違いを表示し、ファイルやハッシュを送信・保存しません。実行や変更も行いません。文字コード・正しい版・サーバーは判定せず、元の5ファイル固定検証器とは別です。

[4ケースの記録](../fixtures/sftp-line-endings-result.json)と[ソース](../../examples/sftp-line-endings-lab.mjs)を公開しています。ローカル`sftp -D`でCRLFのアップロードとダウンロードは30バイトのまま、準備したLFは28、UTF-8 BOM付きは33バイトとBOMを維持しました。終了0でもLFとCRLFのハッシュは異なります。既存OpenSSHサブシステムのある環境で、リポジトリのルートから`node examples/sftp-line-endings-lab.mjs`を実行できます。自動インストールせず、自分で作成した一時ディレクトリだけを片付けます。ネットワーク、WinSCP実行、Nexus GUI、App Storeやスクリプト実行の試験ではありません。権限やサービス反映も別に確認してください。元の実験日は変更しません。



SFTPで接続できても、目的の場所に書き込めるとは限りません。最初は実データを使わず、サーバーの自分専用テストディレクトリへ小さなファイルを送り、Macの別の空フォルダへ取り戻して確認してください。この手順は任意のSFTPクライアントで使えます。製品の購入は必要ありません。

## Mac側とサーバー側の場所を分ける

| 確認すること | OpenSSHの対話型 `sftp>` で使うコマンド | GUIで確認する場所 |
| --- | --- | --- |
| サーバー側の現在位置 | `pwd`、`ls` | リモート側のパスと一覧 |
| Mac側の現在位置 | `lpwd`、`lls` | ローカル側のパスと一覧 |
| サーバー側の移動 | `cd` | リモート側のフォルダ |
| Mac側の移動 | `lcd` | ローカル側のフォルダ |

これらはSFTPセッション内のコマンドです。`cd` / `lcd` に渡す場所は別々です。相対パスは各側の現在位置から解釈されます。絶対パスは `/` から始まりますが、制限付きSFTPアカウントの `/` はサーバー全体の `/` と同じとは限りません。提供元に許可されたパスを確認し、Web URLをそのままファイルパスに置き換えないでください。

保存先は、ホスト・ポート・ユーザー名・リモートパスをまとめて確認します。接続名だけでは不十分です。Linuxのファイル名では大文字・小文字も一致させてください。鍵の指紋が変わった場合は、提供元や管理者を通じて独立に確認します。

## 既存の無料テストパックで確認する

[テストZIPをダウンロード](https://nexusshell.app/assets/downloads/sftp-transfer-check.zip)。空白入りの名前、中国語の名前とUTF-8テキスト、隠しファイル、空ファイル、バイナリの5種類を含む合成データです。インストーラー、資格情報、実行用プログラムは含みません。テストデータはCC0-1.0です。ZIP内の説明は英語・中国語で、この文書が日本語の手順です。

ZIPのSHA-256：`8fb01dafb0893b5edad5b84929db8731a9d8f94bf42ac65d0acde9818786b544`。10月4日に公開した同じパックで、新しい生成物ではありません。

1. Macの新しいフォルダへ展開し、元のコピーを変更せずに残します。
2. サーバー側に自分のアカウントが所有し、書き込める新しいテストディレクトリを選びます。ホストと完全なパスを確認し、隠しファイルを含めて展開済みフォルダを送ります。本番サービスのディレクトリや既存ファイルを上書きしないでください。
3. サーバー側からMacの**別の空フォルダ**へダウンロードします。元のフォルダへ混ぜると、取り戻せなかったファイルが残存コピーで隠れることがあります。
4. MacのTerminalで `cd` と空白を入力し、ダウンロードしたフォルダをドラッグしてReturnを押します。そのフォルダにある `SHA256SUMS` を元のコピーと照合してから、次のコマンドを実行します。

   ```sh
   shasum -a 256 -c SHA256SUMS
   ```

   5ファイルすべてが `OK`、終了ステータスが0になることを確認します。取り戻したファイルから新しい基準値を作らないでください。
5. 必要な権限・所有者・サービスの構文チェックは別に確認します。片付けるときは、自分が作ったテストコピーだけを対象にしてください。

リモートshellは不要です。確認はダウンロード後のMacで行うため、SFTP専用アカウントでも使えます。

## ブラウザで確認したい場合

[既存のローカルファイル検証器（英語UI）](https://nexusshell.app/en/guides/winscp-alternative-for-mac/?utm_source=github-releases&utm_medium=repository&utm_campaign=multi_server_files_202609#transfer-check)で、**取り戻したコピー**の5つのデータファイルを選びます。Macの選択画面でCommand + Shift + .を押すと隠しファイルを表示できます。実データは使わないでください。

元の固定ハッシュを使い、不足・内容変更・重複名・読み取り失敗を区別します。ファイルやハッシュをアップロードしません。READMEやSHA256SUMSなど検証対象外のファイルは別に表示されます。JavaScriptなしでは上のTerminal手順を使えます。

ハッシュ一致は選んだ5ファイルのバイト一致だけを示します。権限、所有者、ACL、余分なファイル、空ディレクトリ、リンク、サーバーの本人性、大容量転送や再開の信頼性を証明しません。元のパックの[生成・検証ソースと記録](../sftp-transfer-check.md#reproduce-the-offline-validation)は公開されています。Nexus ShellのGUIや実サーバーの新しい互換性テストではありません。

## 転送はできても、編集保存が失敗するとき

ファイル自体に書き込めても、一時ファイルを作成して置き換えるための親ディレクトリ権限が足りない場合があります。SSHで `sudo` を実行しても、別のSFTP接続は昇格しません。`chmod 777` や再帰的な所有者変更で解決しようとせず、[既存の権限チェック（英語）](../sftp-write-permissions.md)を使って対象を絞ります。

公式サイト / Homebrew版の外部編集にはリモートshellの追加条件があります。SFTP専用アカウントでの通常の転送と同じ条件ではありません。App Store版は別の転送エンジンで、実際のサーバーとの適合を別に確認してください。保存が完了しても、Webページやサービスへ反映されたことは別の確認です。
